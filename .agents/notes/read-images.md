# 笔记：老师发来的图片（题目照片 / 讲义截图）怎么读

> 什么时候读：老师把**手机拍的题图、卷子照片、讲义截图**丢进 `todo/` 或直接贴在对话里，要你把题目做成课件页时。

## 1. 🔴 铁律：`view_image` 的返回里没有图片内容 ≠ 没有图

看到这样的返回：

```text
[Image was previously shown to you. Image URI: vscode-chat-response-resource://…/file.jpeg]
```

这是**"图已经在你的上下文里了，不用重发"**的意思，**不是报错、不是读失败**。
同一张图重复调多次只会拿到同样的这句话（下图内容仍然在上下文里）。

## 2. 🔴 正确流程（四步，一次成功）

1. **读一次** `view_image`，就一次。
2. **立刻复述**：把图里的**题干文字、选项、答案、图里的关键元素**写出来（写在回复或笔记里）。
   - 复述得出具体内容 ⟹ 读图**成功**，继续干活；
   - 复述不出 ⟹ 才是真的没拿到，这时候去问老师。
3. **有歧义就问**：示意图里"哪个点在上、箭头朝哪、哪条线是虚线"这类**必须准确**的细节，**一句话直接问老师**，
   比自己猜、自己试要快得多。老师明确说过：**不要为了不麻烦老师而浪费时间与成本**。
4. **题目必须带图**：老师给题图，就是要把它**合理地放进课件**——只有题干没有图，学生第一眼就看不到题。
   默认做法是**重画成 SVG**（`components/XxxSvg.vue`）：清晰、配色与字号可控、能做 `showForces` 这类点击分步与图内标注。
   **但不要一刀切地"禁止嵌原图"**：个别**难以重画**的题图（真实照片，如极光、实拍装置、天文照片）**直接嵌原图才是对的**，
   代价是投影到大屏偏糊、也做不了分步标注。
   判断口径：**能画得像样的就画**（示意图、几何图、受力图、坐标图一律画）；**画不像的实拍图就嵌**。
   嵌图把文件放 `courses/<slug>/images/`，用 `<img src="./images/xxx.png" />`。

## 3. 反面教材（本项目真实踩过）

老师给了 5 张题目照片，我误判为"读不到"，然后：

| 我做的事                                     | 实际结果                             |
| -------------------------------------------- | ------------------------------------ |
| 同一张图反复调 `view_image` 5 次             | 返回一模一样，没有多拿到任何信息     |
| 起一个临时 HTTP 静态服务，把图放进浏览器放大 | 多了两个进程、还得记得关             |
| 用浏览器放大 + 截图工具看图                  | 截出来严重失真，比直接读图更差       |
| 准备让老师把 5 道题的文字**手工抄**给我      | 本可自己完成的活，反而要老师手工输入 |

**每次想"确认读图失败"之前，先试着复述一句图里的话。** 这次一复述就发现 5 道题（题干、选项、答案）全都读得清清楚楚。

## 4. 自查

- 🔴 我复述过图里的内容了吗？（没复述过，就没有依据说"读不到"）
- 🔴 同一张图我调了几次？**>1 次**就说明流程走歪了（第二次不会多出信息）。
- 🟡 我有没有为了看图去起服务 / 放大截图 / 换工具打捞？——这类办法通常帮不上忙；真想试的话，先花 30 秒复述一次再决定。
- 🟡 图里必须准确的几何细节，我是**问了老师**还是自己在猜？（问一句通常最快）
