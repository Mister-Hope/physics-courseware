# 笔记：一轮完整的课件风格审查（派给子代理的正本规范）

> 什么时候读：接到"把某门课件按新规范过一遍"的任务时。**先读这份，再动 `courses/<课件>/slides.md`。**
> 规范的正本在 `AGENTS.md`「三、设计系统」，这份笔记是**执行清单 + 判据**，两条冲突时以 AGENTS.md 为准。

## 0. 总原则

- 只改**本课**的 `slides.md`（必要时可改本课 `components/*.vue`、`style.css`），
  ⛔ 不动 `workspace/shared/**`、不动其它课件。
- **不要跑 e2e、不要截图、不要起 dev server**（教师明确要求：不做耗时的验证往返）。
  自检只用：`./node_modules/.bin/unrun scripts/slide.ts <课件> <页号>`（读页源码）+
  `./node_modules/.bin/unrun scripts/style-audit.ts 2>&1 | grep <课件>`（样式审计）。
- **不自造 class**。只用共享原子/组件；需要新样式先在汇报里提出，不要自己加。
- HTML 块内所有行**顶到第 0 列**（缩进 4 空格 = 代码块 → 整页坏掉）；具名 slot 必须
  `<template v-slot:stem>`（不能写 `<template #stem>`）；标签前后各留一个空行。
- 公式与符号一律 `<Latex tex="…" />`，禁止 `v₀`、`θ`、`m/s²` 这类 Unicode 纯文本。

### 0.1 分级与口吻

🔴 / 🟡 的定义、以及"⛔ 软化只针对假门禁、别把话说含糊"（能力边界/使用方法/组件契约照原样写清楚）
的**正本在 [`AGENTS.md`](../../AGENTS.md) 开头的「规则分级」**，本篇不重复。

本文件只补三条执行口径：

- **门禁事实**：CI 只跑 `pnpm lint` + `pnpm build` + `pnpm test:e2e`；e2e 硬失败只有三类（整页渲染失败、越出 980×552、SVG 16px 契约）；
  `pnpm style:audit` 与 `pnpm check:courses` **不进 CI**（style:audit 默认 exit 0，仅建议）。**warn 不等于 error，建议不等于门禁。**
- **软条目的用法**：眼睛看（或量测看数），**只有确实难看的个例才改**——目标是消灭最丑的几处，不是清零数字。
- **拿不准就汇报里问**，不要自作主张。

## 1. 页面标题 —— 三选一（最容易做错的一项）

| 结果                     | 什么时候用                                                                                             | 怎么写                                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| **不写标题**             | 这一页是**引导/提问/过渡/演示/练习**页：页面的核心是一个问题或一段引导语，标题只是把同一句话又概括一遍 | 删掉 `# 标题`；把那句话留在 `.ask` 里；把原标题写进该页 **frontmatter `title:`**（不上屏，保住目录/PDF 书签） |
| **驱动问题型（大档）**   | 标题本身就是这一页的主问题，整页在答它，且**页面上没有另一个等价的 `.ask`**                            | `# 问题？` + 该页 frontmatter 加一行 `class: title-ask`                                                       |
| **主题型（小档，默认）** | 标题只是这一页的**名字**（知识点/环节名）：换一个同义名字，页面照样成立                                | 直接写 `# 名字`（默认就是小档，什么都不用加）                                                                 |

**判据（按顺序问自己）**

1. **"提问只能出现一次"**：页面里已经有 `.ask` 提出同一个问题了吗？→ 有：**删标题**（不然标题和提问重复，还挤掉提问的字号）。
2. 标题是纯导航词（引课 / 小结 / 定义 / 结论 / 回顾 / 思考与讨论 / 扩展内容）吗？→ 是：**删**。
3. 把标题换一个同义的名字，页面还成立吗？→ 成立：**小档**；不成立（标题就是页面要回答的那个问题）：**大档**。
4. 判断不了 → 按"不写标题"处理（整页无标题是仓库 62% 页面的常态），并在汇报里列出来让教师复核。

## 2. 顶部装饰标签 `.tag-icon` —— 建议清掉（🟡）

`<div class="tag-icon …">…</div>` 是给老师看的导航标签（"引课""小结""位移的定义"），学生看不懂也没用。
**建议**改到就顺手清掉（教师认可这个方向），但**别把它当违规去专门开一轮**：

- 标签内容是**这一页的主题** → 提升为页面标题（按第 1 节判据选小档/大档）；
- 标签内容是**导航词**或**章节路径**（"质点 · 物体和质点""时间 位移 · 引入"）→ 直接删（顶栏已经显示章节名与课题名）。

## 3. 提问图标 `<mdi-head-question-outline />` —— 克制（🟡）

- 一页**通常**留一个，且给这一页的**主提问**；
- 页内的次要提问、补充追问、叙述性文字前的问号图标 → 建议删掉；
- 一页里出现两个及以上问号图标，多半是没必要的堆砌 → 建议收敛到一个（页面确实有两问并列、看着也顺眼，可以保留）。

## 4. 定义 → `DefinitionBox`（共享组件，全局已注册，不用 import）

```html
<DefinitionBox term="坐标系" tone="gold">
  <div>
    在参考系上建立<span class="def-term">坐标系</span>（coordinate
    system）：规定<b>原点</b>、<b>正方向</b>和<b>单位长度</b>。
  </div>
</DefinitionBox>
```

- `term` = 定义的名字（左上角浮动标题，跨在框边上）；`tone` = `gold`（默认）/ `blue`（两种定义并排时用不同色）；
- 正文按 **HTML** 写（不要 markdown 语法），公式用 `<Latex tex="…" />`；正文里出现定义名时用 `<span class="def-term">`（颜色自动跟随 tone）；
- **并排两个定义**：外层套 `<div class="def-row">`；
- 已有的 `.card` / `.card-highlight` 里凡是"XX 叫作 YY / YY 是……"这类定义 → 换成 `DefinitionBox`（`.card` 不再用于定义）。

## 5. 结论与提示 → 提示气泡（**尽量不再用左竖线的 `.key`**）

| 语义              | 用什么                                      |
| ----------------- | ------------------------------------------- |
| 这一页的结论/落点 | `<div class="tip-hint">…</div>`（绿）       |
| 答案 / 补充说明   | `<div class="info-hint">…</div>`（蓝）      |
| 易错 / 注意       | `<div class="warn-hint">…</div>`（金）      |
| 禁止 / 错误做法   | `<div class="danger-hint">…</div>`（红）    |
| 必记 / 重点       | `<div class="important-hint">…</div>`（紫） |

- 用法就是 `<div class="tip-hint">文字（可含 `<span>`、`<Latex>`、多个 `<div>` 段落）</div>`，
  **图标由 CSS 自动给，页面里不要写图标标签**；
- `.key` / `.key-blue` / `.key-danger` **不再使用**：结论 / 提示 / 答案一律用上面的气泡，不要新增 `.key`；
- 教师明确不喜欢"左侧一条竖线"那种长相 → 结论、答案、提示一律走气泡。

## 5.5 页面上的「AI 风格」话术 —— 一律清掉

页面上只留**教学内容本身**，不要自造"栏目名"、不要文案腔。教师原话："还是会有一些 AI 风格很重的地方。"

- **自造栏目名**：`带走一句话` / `一句话总结` / `记住这句话` / `划重点` / `敲黑板` / `小贴士` / `温馨提示` / `小锦囊` / `神总结` …
  → **删掉这个标题**，只留下面那句内容；真的需要一个标签就用朴素词（`小结` / `注意`），或者干脆直接讲。
  （实例：`1.x-vectors` 第 20 页原来有一行 `<div class="mini-title"><mdi-sigma /> 带走一句话</div>` —— 删掉，只留那条 `tip-hint`。）
- **文案腔 / 口号体**：对称排比、拟人化口号、江湖口诀式总结
  （如"把方向交给坐标，把计算交给最熟悉的加减法"）→ 改成**直陈述**
  （"矢量既能用几何法求和，也能分解到坐标轴上做加减"）。
- **不打比方**（教师反复强调）：页面文字一律用**学科语言**，不要比喻、拟人、口号式代称。
  - `两条路都得到 T₀` → `两种做法都得到 T₀`；`刹车陷阱` → `刹车的易错点`；
    `位移藏在面积里` → `位移与 v-t 图线下的面积`；`让所有矢量"站到同一起跑线"` → `把矢量平移到共同起点`；
    `把矢量"搬"到一起` → `平移后首尾相接`。
  - 教师原话："我们教师讲课，最起码会说两种方式，什么叫两条路？能不能不打比方。"
- **不用引号做强调/加梗**：`平时说的"时间"` → `日常生活中所提及的时间`。
  真正的专有名词、题面术语（如 `"香蕉球"`）可以保留引号，但**不要拿引号做"梗"或强调**。
- **过渡旁白**：`让我们一起看看` / `接下来` / `你会发现` / `不妨试试` → 删（教师口头会带，不上屏）。
- **海报腔**：感叹号、"重点来啦"、"必看"这类 → 删。
- 已有的 `口诀：…` 要逐个判断：真的是**学生要背的规则**（如"沿绳、沿杆、垂直于接触面"）可以留；
  只是"总结腔"的 → 改直陈述。

## 5.6 气泡密度 —— 由 AI 按每页内容密度决定，不要写死

气泡（`tip/warn/danger/info/important-hint` 与 `DefinitionBox`）的内边距走**共享变量**，谁都可以覆盖：

| 变量               | 默认    | 作用                 |
| ------------------ | ------- | -------------------- |
| `--hint-pad-y`     | 0.8rem  | 提示气泡的上下内边距 |
| `--hint-pad-x`     | 1.15rem | 提示气泡的左右内边距 |
| `--hint-icon-size` | 1.05rem | 提示气泡头部图标尺寸 |
| `--def-pad-y`      | 1.1rem  | 定义气泡的上下内边距 |
| `--def-pad-x`      | 1.35rem | 定义气泡的左右内边距 |

两种用法：

1. **整门课统一调**：本课 `style.css` 的 `:root` 里覆盖（已在 `style-audit` 白名单里，不算越权）；
2. **单页调**（推荐）：在页面的容器上写行内变量，只影响这一页：
   ```html
   <div class="page-grow page-around" style="--def-pad-y:.8rem;--hint-pad-y:.55rem"></div>
   ```

**判据（AI 自己决定）**：内容多、页面快溢出 → 调小（0.5–0.8rem）；
内容少、页面空 → 调大（0.9–1.2rem）；一页里同时有气泡和别的内容时，优先保证**不溢出**。
⛔ 不要把具体数值写进组件/原子（那样每页都长一个样），也不要为了塞下内容去改字号。

## 5.7 提示气泡的**观感**（软建议 —— 不是门禁，别拿它去改版面）

教师原话："气泡一堆字、又不是全宽的，四四方方占掉屏幕一大块，很难看。"
但**他给的是一条尺度，不是一条禁令**：宽度 80% 可以接受、75% 没准也可以、60% 可能就不太行。

- **判断要"字数 × 宽度"一起看**：
  - 又长又窄（大致 ≤60% 页宽 且 >60 字）→ 明显难看，**要处理**；
  - 够宽（大致 ≥75% 页宽）的长气泡 → **可以接受，别动**；
  - 在某个栏里但只有一两行、看着不别扭 → **可以接受，别动**。
- 真要处理时，优先级：**把气泡移到栅格外面横跨整页** > 把长内容提炼进正文/`.ask` 的答案 > 拆成两条短气泡。
- ⛔ **不许**为了"让数字达标"去缩字号、砍物理内容或改版面结构；⛔ **不许**把教师有意为之的版式按这条"改回去"。
  这条的目标是**消灭最丑的那几处**，不是把所有数字清零。

巡检工具（**Lead 侧临时脚本，不入库**；需要时让 lead 重新生成）只能看到"在栏内 / 字数"，
**它给的是"值得眼睛看一眼"的候选，不是违规判定**（宽度得目测或用截图看）。

## 5.8 内页角部装饰（教师口径，软）

- 教师："这个页面本身已经有这个图标了，有点儿画蛇添足。**原则上只是封面页才需要这么干**。"
- 约定：右下角/角落的装饰 SVG（`<CoverDecorationSvg />`、`.cover-decoration`、`abs-br` 淡色图标）
  **默认只放封面**（`layout: course-cover` 的默认插槽）。内页**默认不加**。
- 但这是**审美取向，不是门禁**：内页如果确实有设计意图、看着好看，可以留 ——
  别拿这条去删别人有意画的装饰。
- 已按教师要求清理：`2.1 p17`（连带删掉只剩它用的 `.think-deco` 规则）、`10.4` 一页（同款）。

## 5.9 底部余量 —— 教师认可的尺度：**≥18px，24px 左右最舒服**（不是"必须 ≥24"）

- 教师原话（2026-10-18）："贴边肯定也不行，我建议 18 像素或者 24 像素左右是可以接受的。"
- 事实：`layout: base-flex` 的版面底部内边距是 1.1rem，所以**页面内容撑满时余量上限就是 24.2px**——
  见到"24"是**满格**，不是"刚好达标"，别为凑数去收内容。
- 判据：**<18px 必须收**（收密度 / 收 `mt-*` / 精简一句废话 / 拆页）；
  18–24px 属正常；**>40px 且页面看着空** → 反过来要放大字号/图，或按 §7 疏排。
- 溢出（余量 <0）是硬问题，必须清零。
- ⚠️ **量测经验（踩过）**：`clickAnimation: card` 的入场动画未结束时元素带 `transform`，
  在动画中途读数会偏小（实测同一页 400ms→11.5px、≥900ms→24.2px）。
  **量测必须等 ≥1500ms 且等 `document.fonts.ready`，并且同一页至少跑两遍**——
  否则会得到"假溢出"，然后去改本来没问题的页面。测量脚本还要**跳过被祖先/`<svg>` 视口裁掉的元素**
  （被裁掉的东西屏幕上看不见，但元素矩形仍在画布外，会被误判成溢出：
  `10.4 p20` 的光晕、`6.4 p11` 故意出血的圆都属这一类）。

### 5.6.1 ⚠️ `.key` → 气泡会把页面顶高约 27px（转完必须复查顶出）

气泡比 `.key`（左竖线块）高 **约 27px**（实测：`--hint-pad-y:.58rem` 时约 20px，`.8rem` 时约 27px）。
**把整页的 `.key` 都换成气泡后，原本刚好贴底的页会被顶出 `.page-grow`**（首行叠到标题上、末行被裁），
这是 AGENTS.md 点名的"真会坏页面"两条之一 —— e2e 的「正文越界」一节会报（`E2E_STRICT_BLOCK_FIT=1` 时直接失败）。

**所以：一批 `.key` 转完气泡，必须跑一遍严格 e2e 复查**：
```bash
E2E_COURSE=<slug> E2E_STRICT_BLOCK_FIT=1 ./node_modules/.bin/unrun scripts/e2e.ts
```
报出的页按 §5.6 收密度（页面容器行内 `--hint-pad-y:.5rem` 左右、收 `--page-gap` / `--stack-gap`、收多余 `mt-*`），
或删掉与结论重复的从句（**物理内容不许丢**）。⛔ 不许为了腾高度回退成 `.key`、不许缩小正文字号。

## 6. 对齐一致性（🟡 观感）

- 一页**通常**只有一种**块级**对齐：全居中，或全左对齐；
- "大多数一种 + 一两个另一种"建议统一（例如提问行有 `justify-center`、其余左对齐 → 去掉 `justify-center`）；
- 块**内部**居中（三列卡片各自 `text-center`）不算混排；图/公式居中不算混排；
- 真有意为之的混排（比如整页居中 + 一条左对齐的题面）**可以留**，别为这条去改版面。

## 7. 疏排与铺垫（🟡）

- 内容少的页：把正文包进 `<div class="page-grow page-around">`（块数 ≥2 时），避免内容挤在竖直中段、上下各空一大片；
- **单块内容**的页一般不要用 `page-around`（对单个子项等于居中），要么放大字号/图，要么合并到相邻页；
- 页面越空的页越不要写标题（标题会把"空"衬得更明显）。

## 8. 练习 / 例题页

```md
---
layout: exercise-split
clicks: 2
title: 练习一 位移与路程
---

<template v-slot:stem>

<div><b class="ex-no">练习一</b>　题干……（　　）</div>

<div class="ex-options">
<div><b>A.</b> ……</div>
<div><b>B.</b> ……</div>
</div>

</template>

<div v-click="1">解析第一步……</div>

<div v-click="2">解析第二步——选 <b class="text-accent">C</b>。</div>
```

- **不写页面大标题**；题号用 `.ex-no`；选项用共享 `.ex-options`（两列网格）；答案写进 frontmatter `title:`；
- 有图时图进 `#fig`（**图组件必须有固有尺寸** `width`/`height`，否则栏宽塌成 0、图消失）；
- 题—解分界由布局自动给（有图 = 竖线，无图 = 横线 + 「解析」标签），页面**不用自己画**；
- 解析区里不要再套 `.key`/气泡（分界已经给了）。

## 9. 交付与汇报

1. 逐页过完，跑 `./node_modules/.bin/unrun scripts/style-audit.ts 2>&1 | grep <课件>`，确认**没有新增 error 级**发现（warn 要在汇报里说明是不是本次引入）；
2. 用 `send_message` 给 lead 汇报，格式：
   - **逐页清单**：页号 → 结果（不写标题 / 小档 / 大档）+ 用了哪些原子/组件；
   - **判断不了或吃不准的页**：单独列出来，写清你的取舍理由（教师会复核）；
   - **没有改动的页**：一句话说明为什么不动；
   - style-audit 输出原文。
3. 不要跑 e2e、不要截图、不要起 dev server。
