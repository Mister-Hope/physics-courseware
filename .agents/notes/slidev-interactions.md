# 笔记：点击节奏与交互组件

> 什么时候读：设计/修改**页面里的点击顺序**、写**交互式 Vue 组件**时。这两条是老师反复强调的**教学要求**，不是排版偏好。

## 1. 点击顺序＝上课顺序：先抛问题 → 再出图/演示 → 最后才出结论

- 结论、定义、总结那类元素（通常是 `.key`）**必须是这一页的最后一次点击**，绝不允许先给答案再补过程
- 图和文字分两栏时**不要让图常显**：把图包成第 1 次点击（`<div v-click="1">`），文字与结论依次 2、3…
- 用**显式序号** `<div v-click="2">` 而不是 `<v-clicks>`，才能让 DOM 顺序与讲课顺序解耦（左栏文字先写、右栏图后写，也能让图先出现）
- ⛔ **`<v-click="N">` 不能当包裹标签用**（`speed §1.3` 第 9/10/11 页踩过，整个课件 build 直接挂）：
  markdown-it 不把**带属性**的 `<v-click="1">` 当 HTML 块，会把它转义成 `<p>&lt;v-click="1"&gt;</p>`，
  留下一个悬空的 `</v-click>` → Vue 编译报 `Invalid end tag`，`pnpm build` / `pnpm test:e2e` 全失败。
  正确写法是**属性形式**（写在元素上）：`<div class="three-col" v-click="1">…</div>`；
  只有**不带属性**的 `<v-clicks>` / `<v-click>` 才允许当包裹标签。
- 唯一例外：例题的"题目配图"属于题干，可以常显

## 2. 点击只允许"出现新元素"，绝不允许移动已有元素

相邻两次点击之间，上一步已经可见的元素必须一动不动——否则学生正看着图，文字一出来整页往上跳，眼睛要重新找。

- Slidev 原生 `v-click` / `<v-clicks>` 用 **opacity 隐藏、保留占位**，所以它们写的页面天然不跳 ✓
- **坑：组件里按 `$clicks` 分步时不要用 `v-if`**——真删真插会把下面的元素（尤其 `.page-grow` 里垂直居中的整块）顶跑。
  改用 `visibility: hidden` 占位：
  ```html
  <div class="vp-hint" :class="{ 'vp-hidden': step < 1 }">…</div>
  ```
  ```css
  .vp-hidden {
    visibility: hidden;
  }
  ```
  （`courses/1.x-vectors/components/VectorPlayground.vue` 是正面例子。）**固定尺寸的 SVG 内部**用 `v-if` 无妨，跳出 DOM 布局的才要改
- **操作提示这类长期存在的元素放最上面**，不该被后出的内容顶下去
- **例外：手风琴式**——有意"依次展开讲述、再收起来"的段落，允许位置变化；除此之外一律不许位移

## 3. "点击分步动画"组件的标准做法

> ⚠️ **先分清两种交互**（`speed §1.3` 第 12 页踩过）：
>
> - **点组件本身演示一次**（跑一圈、播放、炮弹出膛…）→ 用 `@click` **直接触发**，**不要绑 `$clicks`**。
>   原因有两个：① **Slidev 里鼠标点击不推进点击步**（只有空格 / → / 翻页笔才推进），绑 `$clicks` 的动画鼠标点不出来；
>   ② 老师的意图是"交互式的东西，点它一下它就该动"，不该占用翻页的点击。跑完再点可以重跑。
> - **组件内部跟着翻页逐步呈现**（图先出、再出标注、再出结论）→ 才用下面的 `$clicks` 写法。
>
> 一句话：`$clicks` 是"翻页节奏"，`@click` 是"交互演示"，别混。

1. 页面 frontmatter 写 `clicks: N` 给这一页定点击数（**不写就永远是 0**）
2. 组件里拿当前步：

```ts
import { useSlideContext } from "@slidev/client";
import { computed } from "vue";

const { $clicks } = useSlideContext();
const step = computed(() => Math.max(0, Math.min($clicks.value, 3)));
```

3. 各步要出现的元素**始终渲染**，只切 `visibility`（见上），**不要**叠 4 个 `<div v-click>`（会渲染 4 份）
4. 数值必须由**真实学科公式**算出（`computed` 里实现），随参数真实变化，不拍脑袋

## 4. 可拖拽交互的热区与提示

- 细箭头/细线用 `r=16~18` 的**透明圆**当拖拽热区（`fill="transparent"` + `cursor: grab`）
- 拖拽用 `setPointerCapture`，指针坐标换算成 viewBox 用户单位后再取整/吸附
- 拖拽点**不写操作提示**（"拖动××试试"这类话一律不上屏，见下 §5）：做得让学生一眼就想动手即可
- 拖拽点本身画成**很透明的灰圆**（如 `fill="rgba(148,163,184,0.18)"`），并且**画在箭头/图形的层级之下**——完整的箭头要露出来，不能被实心圆盖住；接收指针事件的透明热区可以另画一层放在最上面

## 5. 屏幕上绝不允许出现写给 AI / 开发者的备注

`（热区已放大）`、`（续）`、`TODO`、`这里可以拖` 这类话出现在学生看的屏幕上就是**教学事故**。
屏幕上只放**给学生看的操作指引**，而且要像老师会对学生说的话；所有"留给下一轮 AI 看的备注"一律写进
`content/思路.md`、`courses/<slug>/README.md` 或代码注释里。
