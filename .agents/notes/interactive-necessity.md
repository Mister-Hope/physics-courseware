# 交互组件必要性评估指南（先判断"要不要做交互"，再动手）

> 这是**指南**，不是铁律：同一节课用滑块还是用示意图，最终按"这一页要学生看清什么"判断。
> 它的用途只有一个：**在写 `CourseSlider` / 拖动热区之前，先回答"这个交互有没有必要"**——
> 避免"每个知识点都配一个滑块"，把课堂演示变成数值玩具。
>
> 相关：点击节奏与分步规则见 [`slidev-interactions.md`](./slidev-interactions.md)；共享组件 props 见 [`shared-components.md`](./shared-components.md)。

## 0. 一句话判据

**只有当"参数变化、结果随之变化"这件事本身就是教学对象时，才值得上滑块。**
其余情形，先想"一张干净的示意图 + 几步点击"能不能讲得更清楚。

## 1. 三个问题（答不出就别做滑块）

1. **这个结论需要"数值"吗？**
   学生只要看"有 / 没有、变大 / 变小、朝哪个方向、疏 / 密"——就**不需要**滑块（定性即可，**也不要**硬塞数值）。
2. **要数值的话，它随哪些物理量变、变到什么程度？学生必须"亲手调出来"才会信吗？**
   "亲手把 $r$ 变小、看 $F$ 涨得更快"就是典型：这种"自己动手建立关系"的体验，滑块比老师口述强得多。
3. **不做交互，用示意图 + 点击分步能不能讲明白？**
   能 ⇒ 做示意图。**这一问必须真的想过**，不能默认"交互更高级"。

## 2. 值得做滑块的两种情形

- **A. "剧烈程度"本身就是教学对象**（越…越…）：
  静电力随距离 / 电荷量的变化、尖端放电随曲率半径与电压、匀强电场的强弱……
  学生**调参数、看读数与图形同步变**，才能把"关系"变成直觉。
- **B. 确实要衡量，且测量结果随参数变化**：
  教材或实验给了可算的关系（$F = k\dfrac{q_1q_2}{r^2}$、$Q = ne$、$E = k\dfrac{Q}{r^2}$、$F = qE$）。
  这时滑块是把公式"演活"的最短路径，但读数必须是**真实公式**算出来的。

## 3. 不该做滑块的情形（含 §9.1 的真实教训）

- **结论是一个"动作 / 过程"，不是一条函数曲线。**
  **反例（2026-10，§9.1 第 9 页）**：要强调的是"**两个完全相同的金属球接触后电荷平分**"，举的两个例子是
  $+Q$ 与 $0$ → 各 $+\dfrac{Q}{2}$；$+Q$ 与 $-3Q$ → 各 $-Q$。
  第一版做成了"固定球 A 为 $Q$，拖滑块把球 B 从 $+Q$ **连续**调到 $-3Q$，底下用两条公式算平均值"——
  **学生看到的是两条公式在动，看不到"接触"这个动作**；而且"平分"只对**完全相同的金属球**成立、答案只取两个**离散**结果，
  连续滑块反而把要点掩盖了。
  **正确形态**：点击分步的"接触前 → 接触 → 分开"动画，两个例子各演一遍，结果（$+\dfrac{Q}{2}$、$-Q$）在"分开"那一击出现。
- **结论只对离散情形成立**（平分只对"完全相同"的球；$n$ 只能取整数）→ 用**离散档位**（点击 / 档位选择），不要连续滑块。
- **"调了也不改变结论"的假交互**：旧稿 §9.1 的滑块调连续 $Q$、再除以 $e$，结果必然不是整数，与"电荷量是 $e$ 的整数倍"直接冲突。
- 只是"把教材的数据换个参数复现一遍"。
- **形态变化类**（箔片张合、箭头方向、场线疏密、微粒运动轨迹）→ 定性演示即可，不要为了"有交互"而编读数。

## 4. 决定要做交互时，做对的样子

- 交互对象必须是**学生该动手的那个量**（可拖的点、电荷量、距离、电压），不是"公式里的中间量"。
- 一个组件里**通常**最多 2 个滑块，第三个就该考虑拆页；**但"同一条式子里的几个自变量"不算凑数**——
  例如 $F = k\dfrac{q_1q_2}{r^2}$ 的 $q_1$、$q_2$、$r$ 同页是合理的（学生要看出"改一个只动一部分"）；
  把三个**互不相干**的量塞进一个组件才叫该拆。
- **先给干净现象、再给读数**：第一眼只看到现象与问题，读数 / 标注点击后才出（与"先问后答"一致）。
- **动画要"演动作"**：接触、分开、移近、张开、吸附、漂移——而不是只让数字跳。
- 读数用**真实公式**算；极值不出 `NaN / Infinity`，箭头不出画布（见 `AGENTS.md` 八）。
- 屏幕上不写操作提示（"拖动试试"）；热区用很透明的弱提示、画在箭头层级之下。

## 5. 写进方案的"一句话自证"

每个交互组件，在方案里写一句：**"它必须是交互、而不是示意图，因为 \_\_\_\_\_\_。"**
写不出来 ⇒ 把它改成示意图 / 点击分步。
复核时也照这句问：答"因为可以调参数"**不算**；要答"因为学生亲手调 $r$ 才能看到 $F$ 按平方变"。

## 6. 优先级

**示意图（常显） ＜ 点击分步 ＜ 滑块**
只有在"连续变化 + 实时读数"本身就是教学对象时，才升到最右。
